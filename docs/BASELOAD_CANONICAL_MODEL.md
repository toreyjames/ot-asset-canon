# Baseload Canonical Model

## Anchor Definition
Baseload is a multi-scale industrial intelligence system that maps:

`capital -> infrastructure -> operational reality`

Across three connected zoom levels:

`Strategic Map -> Site Intelligence -> Mission Map`

## Scale Hierarchy

`Nation/Region -> Company -> Site -> Facility -> Line -> Asset`

## Core Maps

### 1) Strategic Map
Purpose: macro industrial campaign map of the U.S.

Questions:
- Where is industrial investment flowing?
- Which sectors and regions are forming strategic clusters?
- Which companies are expanding or retooling?

### 2) Site Intelligence
Purpose: bridge macro signals to real sites/facilities.

Site object includes:
- company
- facilities
- programs
- investment events
- evidence links

### 3) Mission Map
Purpose: operational topology of a facility.

Shows:
- physical structure
- control hierarchy
- dependencies
- confidence states
- issues/mismatches

## Canonical Relationships
- Company owns Site
- Site contains Facility
- Facility contains Line
- Line depends on Assets
- Program funds Site
- Investment modifies Facility

## Baseload Doctrine
- Reality first: model is grounded in observed signals.
- Provenance required: every claim traces to sources.
- Multi-source epistemology: confidence derives from cross-source agreement.
- Continuous verification: models refresh as evidence changes.
- Machine readability: state exists as graph, not slideware.

## Mission Map Layers
- Physical layer: site/facility/line/cell/machine
- Control layer: sensors -> PLC -> HMI/servers
- Network layer: field/control network topology
- Dependency layer: power -> control -> process
- Confidence layer: observed / inferred / disputed / unknown

## Detection Concepts
- documented asset not observed
- observed asset not documented
- duplicate identity
- missing dependency
- topology contradiction

## Navigation Contract
All screens are zoom levels of the same system:

`Strategic Map -> Company -> Site -> Facility -> Mission Map -> Asset`

## Visual Doctrine
- Monochrome first: black / white / industrial gray / muted green accent
- Structured grids and technical typography
- Diagram-first communication
- Minimal marketing language
- Interface must feel operational, not promotional

## Product Test
A new user should infer immediately:
- where industrial capacity is forming
- which sites/facilities matter
- what infrastructure exists
- what dependencies exist
- where confidence and gaps differ
